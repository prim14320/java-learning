## 问题 1：添加学生时，学号校验时机错误

### ❌ 我原来的写法（错误）
```java
Student s = new Student();
while (true) {
    s.setSid(sc.next());
    if (!checkid(student, s.getSid())) {
        student.add(s);    // ← 学号合法就立刻 add 进集合
        break;
    } else {
        System.out.println("该学号已存在，添加失败");
    }
}
// 然后才在后面填 name / age / address
s.setName(sc.next());
s.setAge(sc.nextInt());
s.setAddress(sc.next());
```

### ✅ 正确写法
```java
Student s = new Student();
while (true) {
    String sid = sc.next();
    if (!checkid(student, sid)) {
        s.setSid(sid);     // 只先记录学号
        break;
    } else {
        System.out.println("该学号已存在，添加失败");
    }
}
s.setName(sc.next());      // 填完其他信息
s.setAge(sc.nextInt());
s.setAddress(sc.next());
student.add(s);            // 最后才 add 进集合
```

### 💡 为什么错
原来的写法依赖"对象是引用传递"——先把对象地址塞进 list，后面再改对象内容，因为 list 里存的是地址，所以能改到。**但这套逻辑是巧合**：一旦学号合法与否的判断和后面的输入脱节，就可能把一个"信息不全的空壳学生"加进列表。正确顺序应该是：**把所有信息填完 → 最后再 add**。

## 问题 2：`toString()` 里的对象名写错

### ❌ 我原来的写法
```java
return "StudentSystem{" + ...   // 类名是 Student，却写成 StudentSystem
```

### ✅ 正确写法
```java
return "Student{" + ...
```

### 💡 为什么
`toString()` 返回的字符串里应体现**当前类的真实名**。写错类名虽然不报错，但打印出来会让人困惑：明明是 Student，却显示 StudentSystem。

## 问题 3：`toString()` 里 int 类型用了单引号

### ❌ 我原来的写法
```java
", age='" + age + '\''    // age 是 int，不该加单引号
```

### ✅ 正确写法
```java
", age=" + age            // int 直接拼字符串
```

### 💡 为什么
单引号 `'\''` 是给 **String / char** 类型的值包起来的。`age` 是 `int`，拼字符串时不需要单引号，直接 `+ age` 即可。误加单引号会导致打印成 `age='20'` 这种奇怪样子。

## 问题 4：每个方法都重复 `new Scanner`

### ❌ 我原来的写法
```java
public static void addStudent(...) {
    Scanner sc = new Scanner(System.in);   // 每个方法都写一遍
}
public static void deleteStudent(...) {
    Scanner sc = new Scanner(System.in);   // 又写一遍
}
```

### ✅ 正确写法
```java
public static void main(String[] args) {
    Scanner sc = new Scanner(System.in);   // 全局只建一个
    addStudent(student, sc);               // 传下去用
}
```

### 💡 为什么
重复创建 `Scanner` 浪费资源，且多个 Scanner 共享 `System.in` 容易出 bug。**全局建一个、传参复用**更规范。

## 问题 5：退出用了 `System.exit(0)` 强杀进程

### ❌ 我原来的写法
```java
case "5" -> {
    System.out.println("退出");
    System.exit(0);    // 直接调虚拟机退出，程序被"杀死"
}
```

### ✅ 正确写法
```java
loop:
while (true) {
    ...
    case "5" -> {
        System.out.println("退出");
        break loop;    // 跳出外层循环，让 main 正常结束
    }
}
```

### 💡 为什么
`System.exit(0)` 是人为终止整个 JVM，很粗暴。而用**带标签的 break** 跳出循环，程序会按正常流程走完 `main`，更规范、更可控。而且 `System.exit(0)` 里的 `0` 是给操作系统的退出码，一般不该在主流程随意调用。

## 问题 6：`checkid` 和 `getIndex` 代码冗余

### ❌ 我原来的写法
```java
public static boolean checkid(ArrayList<Student> stu, String sid) {
    return getindex(stu, sid) >= 0;
}
public static int getindex(...) { ... }   // 名字还写成 getindex（不规范）
```

### ✅ 正确写法
```java
public static boolean checkid(ArrayList<Student> student, String sid) {
    return findIndex(student, sid) >= 0;   // 复用一个查找方法
}
public static int findIndex(ArrayList<Student> student, String sid) { ... }
```

### 💡 为什么
`checkid` 本质就是"找不找得到"，复用 `findIndex` 返回的索引即可，避免重复写查找逻辑。方法命名保持 `findIndex`（驼峰）比 `getindex` 更规范。
